## 4. Architecture and Event Flow Review

### 4.1 Event Flow Architecture

```
TaskService.assignAgent()
  └─> hermesAdapter.dispatchTaskInstruction()    [POST /v1/runs]
        └─> terima run_id dari Hermes
  ├─> taskRepo.setHermesRunId(taskId, runId)     [persist ke SQLite]
  ├─> hermesEventBridge.registerRunTaskMapping(runId, taskId)
  └─> hermesEventBridge.startPolling(runId)      [async, fire-and-forget]
        └─> _pollRunEvents() → _fetchAndProcessRunEvents()
              ├─> GET /v1/runs/{runId}/events [SSE: text/event-stream]
              ├─> parse SSE lines incrementally (id:/event:/data:, CRLF/LF, chunk boundaries)
              ├─> each event normalized + reconciled immediately after delimiter
              ├─> lastEventId/lastSeq updated ONLY after successful reconciliation
              ├─> _normalizeSSEEvent() [Hermes event → internal schema]
              ├─> StateReconciler.reconcile() [idempotent, transactional SQLite]
              │     └─> eventPublisher.publish*() [WebSocket broadcast]
              └─> terminal event → stop polling + clean mapping
        └─> AbortController cleanup on stop/shutdown
```

### 4.2 Key Design Decisions

| Decision | Rationale |
|----------|-----------|
| SSE event ID as opaque string | No `parseInt` without API contract proof; avoids assuming numeric IDs |
| Incremental per-delimiter processing | Each event reconciled as soon as its delimiter is received; no waiting for stream end |
| `lastEventId`/`lastSeq` advance only after success | Failed events remain eligible for replay; checkpoint never advances on failure |
| Bounded exponential backoff (1s→30s, 2x, max 5 failures) | Prevents tight reconnect loops; consistent policy for all retryable failures |
| Fire-and-forget `startPolling()` | HTTP response does not wait for SSE lifecycle |
| `runTaskMap` preserved on poll stop | Mapping kept for potential reconnect; cleaned only after terminal event |
| `HERMES_DEFAULT_AGENT_ID` explicit only | No implicit `inst_demo_hermes` fallback for live events |
